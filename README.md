# Godot Addressable

**Version 0.1.0 — experimental. APIs, catalog formats and packaging behavior may change.**
This is an early addon for evaluation, not a promise of production readiness or
drop-in compatibility with Unity Addressables.

Lightweight Inspector references, content catalogs, on-demand PCK delivery, and
owned asynchronous Resource loading for Godot. The editor/runtime use GDScript;
an optional C# facade is provided in the `GodotAddressables` namespace.

## Repository and installation layout

```text
addressable/                       # Any local checkout name is fine.
  LICENSE
  README.md
  project.godot                    # Open this to develop and run the addon.
  demo/addressables/api/           # One log-only data-Resource example.
  addons/
    addressables/                  # Keep this addon path inside your Godot project.
      plugin.cfg
      runtime/
      editor/
      dotnet/
      docs/
      tests/
```

The repository is named `godot-addressable`; the local directory may be named
`addressable`. The addon itself uses `res://addons/addressables/`. These names
serve different purposes and do not need to match.

1. Copy `addons/addressables/` into your project's `addons/` directory.
2. Wait for Godot to import the scripts, then enable **Project → Project Settings
   → Plugins → Addressables**.
3. Use a Godot .NET project if you need the C# facade. In a GDScript-only project,
   omit the optional `dotnet/` folder; a .NET editor can otherwise try to export
   C# files without a matching solution.

## Develop in this repository

1. Open the root [project.godot](project.godot) with **Godot .NET 4.6.3**;
   install .NET SDK 8 for C# development.
2. Wait for import; the Addressables editor plugin is already enabled.
3. Select [demo/addressables/api/build.tres](demo/addressables/api/build.tres),
   then **Project > Tools > Build selected Addressable Content**.
4. Press **F5**, or run [main.tscn](demo/addressables/api/main.tscn) with F6.
   Read Output: the example prints `PASS API flow` and exits.

Edit `addons/addressables/` directly. The example uses that exact source through
`res://addons/addressables/`; no addon copy or external application project is
needed for this development loop. The single example remains GDScript and
plain Resource data. [GodotAddressable.csproj](GodotAddressable.csproj) compiles
the C# facade directly with Godot.NET.Sdk 4.6.3 and net8.0; `global.json` selects
an installed .NET 8 SDK. Run `dotnet build GodotAddressable.csproj` from the root,
or use the .NET editor's build action. Generated test-project copies are excluded
from this build. The broader integration suite also exercises the C# facade.

This pins the development host to 4.6.3; the addon's documented newer-reader
compatibility is unchanged. To develop with another .NET engine version, match
the project SDK to that editor version.

See the [short API example guide](demo/addressables/README.md). Generated catalogs,
PCKs, caches and logs stay outside Git. A fresh clone needs the content-build step
before its first run; repeat it after changing the sample data/references.

For installation into another application, copy only `addons/addressables/`.
The root project and `demo/` are development files, not addon dependencies.

## Quick start

Declare a lightweight field and drag a target asset into it:

```gdscript
@export var prefab: AddressableReference
```

```csharp
[Export(PropertyHint.ResourceType, "AddressableReference")]
public Resource? Prefab { get; set; }
```

Create and save an `AddressablesBuild` resource, add `AddressableGroup` entries,
and use **Project → Tools → Build selected Addressable Content**. Build output
contains a catalog and hashed PCK files, including a shared pack when needed.

```gdscript
var assets := Addressables.new()
add_child(assets)
var issue := assets.configure(catalog, "https://cdn.example.invalid/release-001")
if not issue.is_empty():
    push_error(issue)
    return

var handle := assets.load_asset(prefab, "PackedScene")
await handle.wait()
var scene := handle.get_result() as PackedScene
if scene == null:
    push_error(handle.error)
    handle.release()
    return

var instance := scene.instantiate()
add_child(instance)
# Keep the handle while the feature uses the asset.
# After removing instances, pooled objects and other external references:
instance.queue_free()
handle.release()
await assets.shutdown()
assets.queue_free()
```

This fragment belongs inside an async Node method. `catalog` is a validated JSON
dictionary generated by the builder; replace the `.invalid` URL with your host.
Use the [complete setup and lifecycle examples](addons/addressables/docs/USAGE.md)
for a controller that can close while loading.

## What is included

- Single/multiple target drag-and-drop that stores keys and paths rather than
  direct heavy Resource references.
- UID-aware authoring, catalog validation, dependency collection and shared PCKs.
- Export filtering that keeps optional assets out of the base package.
- Local pack or direct HTTPS delivery, SHA-256 verification and persistent cache.
- Shared in-flight operations, typed handles, ownership scopes and explicit release.
- Resource failure/retry handling, cancellation, pause-safe processing and shutdown.
- An optional main-thread C# facade with `CancellationToken` support.

There is no dependency on an application-specific model, enum, service or asset.

## Testing

The editor/runtime target Godot 4.6 and newer 4.x releases. Native suites have
been validated on Godot .NET 4.6.3 and 4.7.2 on Windows, including C#. Later
releases still need regression testing; this is not a guarantee for every future
engine. Run from this repository root with Python 3.10+ and .NET SDK 8:

```text
python tools/check_repository.py
python addons/addressables/tests/run_tests.py --godot "PATH/TO/Godot_v4.6.3-stable_mono_win64.exe" --stage-engine
```

`--godot` accepts a path; no developer's installation path is hard-coded. The
current integration suite creates a Windows Desktop export preset and detects
the optional C# test branch using a `mono` executable name. It is therefore
**currently validated on Windows**, not advertised as a cross-platform suite.

The runner uses a local HTTP server and writes generated engine/projects/cache/
profiles under `addons/addressables/.test_work/`. The full-pass report and logs
are ignored by Git. Do not ship them. CI currently checks repository hygiene and
Python syntax; see [CI.md](CI.md) for the native integration-test follow-up.

Catalogs record the producer engine's major.minor. A newer minor in the same
major is accepted; an older reader, different major or different platform is
rejected. Unchanged 4.6.3-built demo PCKs were also loaded on 4.7.2 in a clean
client. The native loader still validates the actual PCK/resource formats; test
your own content when upgrading. See the [compatibility policy](addons/addressables/docs/CONTENT_FORMAT.md).

## Experimental limitations

- No remote catalog activation, hot replacement/unmount, download resume, label
  queries, content encryption or tracked-instance API.
- The C# facade does not yet expose scopes, predownload or byte-level progress.
- File hashing and local copying are synchronous and need profiling with real packs.
- Releasing an asset does not unmount a PCK, delete disk cache or immediately free
  native/C# memory retained elsewhere. Explicit release/disposal is recommended.
- HTTP requires a direct HTTPS URL; loopback HTTP is an explicit test override.
- The default timeout is an inactivity/stall timeout, not a total transfer deadline.
- Mobile devices and production TLS/CDN behavior still need target-environment tests.

Build and export matching content together. For CI exports, use
`addons/addressables/editor/export_cli.py`: Godot can log an export error while
returning zero. The wrapper treats either an engine error or `ERROR:` output as
failure and does not delete old output files.
